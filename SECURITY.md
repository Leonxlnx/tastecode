# Security policy

## Supported versions

Only the latest published beta receives security fixes. Update to the newest release before
reporting a problem that may already be fixed.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Email
[hello@tasteskill.dev](mailto:hello@tasteskill.dev) with:

- the affected TasteCode version and operating system
- a concise description of the impact
- reproducible steps or a minimal proof of concept
- any relevant logs with credentials, tokens, personal data, and private source removed

Please give the maintainers time to investigate before publishing details. The maintainers
will coordinate status and disclosure through the reporting email.

## Sensitive data

Never attach provider tokens, API keys, credential-store exports, private repositories, or
unredacted logs to a report. TasteCode credentials must remain with the provider or the
operating-system credential store and must never be committed to this repository.

For non-security bugs, use [GitHub Issues](https://github.com/Leonxlnx/tastecode/issues).
